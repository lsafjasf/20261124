# 4:2:0 色度上采样半像素实验

这是一个只使用 Go 标准库的可复现实验，用来重现并隔离转码后高对比边缘的蓝橙彩边。实验从同一份合成 4:4:4 图像、同一份 4:2:0 色度平面出发，只改变色度上采样的坐标约定和分块原点，不修改亮度，也不对 `Cb/Cr` 做任何全局缩放。

## 结论

- 错误版把色度样本放在 2x2 亮度块的左上角：`q_wrong = x/2`。
- 修正版把色度样本放在 2x2 亮度块中心：`q_fixed = (x+0.5)/2 - 0.5 = x/2 - 0.25`。
- 两者相差 `0.25` 个色度样本，也就是 `0.5` 个亮度像素。错误版的重建位置是 `x+1.0`，修正版是 `x+0.5`。
- 默认夹具为 `19x11`，色度平面 `10x6`，分块 `8x8`。错误版对参考图的最大 `|dR|+|dG|+|dB|` 为 `277.944183`，修正版为 `142.807526`；单像素峰值降低约 48.6%。
- 修正版的左右两像素边缘响应对称，错误版把响应整体推向一侧，形成单侧蓝偏。没有使用整体降饱和。
- 整图与全局坐标分块的结果逐像素完全一致；块内局部坐标控制组会产生明显接缝，证明分块必须保留绝对坐标。
- 奇数宽度 `19` 的最后一列仍映射到其真实中心 `18.5`，`oddWidthSampleShift=0`；`19` 宽与 `20` 宽左侧裁剪的坐标和色度输出逐像素一致。

## 复现

要求 Go 1.21 或更高版本；模块没有第三方依赖。

```bash
go test ./...
go run ./cmd/chroma-exp -out artifacts/chroma-halfpixel
```

可覆盖实验参数：

```bash
go run ./cmd/chroma-exp \
  -width 19 -height 11 -block-width 8 -block-height 8 \
  -out artifacts/chroma-halfpixel
```

程序是确定性的，不使用随机数、当前时间或外部数据。`report.json` 记录了输入 YUV 与参考 RGB 的 SHA-256。

## 坐标与权重

色度坐标 `q` 对应的亮度位置是 `2q+1`。默认夹具边缘在 `x=10`，下表给出完整坐标和双线性权重：

| x | 错误 q | 错误亮度位置 | 错误权重 | 修正 q | 修正亮度位置 | 修正权重 |
|---:|---:|---:|---|---:|---:|---|
| 0 | 0.00 | 1.0 | 0:1.000, 1:0.000 | -0.25 | 0.5 | 0:1.000, 0:0.000 |
| 8 | 4.00 | 9.0 | 4:1.000, 5:0.000 | 3.75 | 8.5 | 3:0.250, 4:0.750 |
| 9 | 4.50 | 10.0 | 4:0.500, 5:0.500 | 4.25 | 9.5 | 4:0.750, 5:0.250 |
| 10 | 5.00 | 11.0 | 5:1.000, 6:0.000 | 4.75 | 10.5 | 4:0.250, 5:0.750 |
| 18 | 9.00 | 19.0 | 9:1.000, 9:0.000 | 8.75 | 18.5 | 8:0.250, 9:0.750 |

左边界通过复制边缘样本并归一权重处理。右边界同样夹到最后一个有效样本。完整 X/Y 表见 `coordinates.csv`。

## 分块对照

`wrong_whole_vs_tiled_max` 和 `fixed_whole_vs_tiled_max` 比较同一版本整图执行与 `8x8` 分块执行的最大绝对色度差。两者均为 `0`，说明全局坐标分块没有引入接缝。

| 块 | 区域 | 错误整图/分块 | 修正整图/分块 | 块内局部原点控制 | 错误/修正最大差 |
|---:|---|---:|---:|---:|---:|
| 0 | [0,0)-[8,8) | 0 | 0 | 0.000 | 1.342 |
| 1 | [8,0)-[16,8) | 0 | 0 | 170.478 | 42.620 |
| 2 | [16,0)-[19,8) | 0 | 0 | 170.478 | 9.013 |
| 3 | [0,8)-[8,11) | 0 | 0 | 5.370 | 0.000 |
| 4 | [8,8)-[16,11) | 0 | 0 | 134.427 | 34.949 |
| 5 | [16,8)-[19,11) | 0 | 0 | 134.427 | 0.000 |

“块内局部原点控制”故意把每块的首像素重新映射为局部 `0`，用于证明这个常见实现错误会造成接缝；它不是修正路径的一部分。

`pixels.csv` 的 `d_cb`、`d_cr`、`d_r`、`d_g`、`d_b` 均为 `错误版 - 修正版`，`abs_rgb = |d_r|+|d_g|+|d_b|`。边缘第一行 `y=0` 的代表值：

| 10 | 42.619504 | -34.221264 | -47.978212 | 9.771731 | 75.521761 | 133.271704 | 0 | 133.271704 |

错误版在 `x=9` 出现明显的红降、蓝升单侧色偏，并在 `x=10` 恰好落在右侧样本上；修正版把误差对称分到边缘两侧。所有 `19x11` 像素的完整记录在 `pixels.csv`。

## 奇数宽度

- 色度宽度使用 `(width+1)/2`，不是 `width/2`。
- `19` 宽的最后一个色度样本只平均实际存在的第 `18` 列，不补未知像素。
- 最后一列 `x=18` 的修正映射为 `q=8.75`，对应亮度中心 `2*8.75+1=18.5`，没有偏移。
- 测试同时运行 `19x11` 与 `20x12`，比较左侧 `19x11` 裁剪：坐标、错误版色度和修正版色度逐项完全相等。
- 分块覆盖测试包含最后一个 `3x8` 和 `3x3` 部分块，没有重叠或漏列。

## 不降饱和

修正只改变几何位置，没有对颜色做整体降饱和：

- 亮度平面原样传递，实验记录的 `maxLumaDelta=0`。
- 双线性权重每轴和为 `1`，常色度平面在任意分块策略下保持原值；测试使用 `Cb=192` 验证无衰减。
- 输出平色区的 `Cb/Cr` 与全分辨率参考完全一致。
- `report.json` 固定记录 `globalDesaturation=false` 和 `lumaModified=false`。

## 产物

运行命令后生成：

- `pixels.csv`：逐像素参考、错误版、修正版、色度差、RGB 差和参考误差。
- `coordinates.csv`：逐 X/Y 坐标、两个样本索引、双线性权重和坐标差。
- `blocks.csv`：逐块整图/分块一致性、局部原点控制组、错误/修正最大差。
- `report.json`：夹具尺寸、策略、完整坐标/权重/分块数据、汇总和输入哈希。
- `reference.png`、`wrong.png`、`fixed.png`：可直接目视比较。
- `diff_amplified.png`：`错误版 - 修正版` 的有符号 RGB 差，以 128 为中心放大 8 倍。

核心实现位于 `internal/chroma/coord.go` 和 `internal/chroma/resample.go`，实验矩阵位于 `internal/experiment/run.go`。

## 适用边界

本实验采用居中式 4:2:0 色度采样位置，即 `4:2:0` 样本位于 2x2 亮度块中心。这是 JPEG 等格式的常见几何约定。若上游格式或元数据明确声明左对齐色度位置，则正确的映射公式不同；此时不能直接套用本实验的 `Centered`。实验验证的是坐标、权重、分块与奇数宽度的几何不变量，不替代具体解码器的格式解析。
