# Opus 风格丢包恢复对比（Go 原生，零外部依赖）

在两种网络丢包模式下，对比三种接收器侧恢复策略，并记录恢复段样本数、波形误差与逐帧状态链。

- **Opus 内建 FEC（`fec`）**：发送端把前一帧的降级冗余（低通 + 8bit 量化）捎带到下一帧分组；丢包后由下一到达分组中的带内 FEC 重建。
- **静音插入（`silence`）**：丢失帧输出零样本，保留帧长契约。
- **独立 PLC（`plc`）**：仅基于接收器历史输出，做自相关基音搜索、周期延拓、逐突发能量衰减与恢复交叉淡化。

## 目录结构

- `audio/`：WAV 读写、PCM 分帧、语音风格信号生成、低通与量化。
- `sim/`：分组与信道丢包、三种接收器、PLC 引擎、误差度量与反回填审计。
- `main.go`、`report.go`、`markdown.go`：场景编排与产物输出。
- `output/`：运行后生成的 WAV、丢包掩码、`results.json` 与 `report.md`。

## 丢包素材

- 信号：48 kHz、单声道、16bit，60 帧 × 960 样本（20 ms/帧，共 1.2 s）。
- 孤立丢包：帧 6、18、34、49，共 4 个单帧事件（相邻帧均到达，FEC 可修复）。
- 连续丢包：帧 10–13 与帧 40–43，两段 4 帧突发，共 8 帧。
- 掩码文件：`output/mask_isolated.txt`、`output/mask_burst.txt`（每行 `帧号 1/0`）。

## 运行与测试

```bash
go test ./...      # 含状态链、FEC 回退、反回填审计、WAV 往返测试
go run .           # 生成 output/ 下全部素材与报告
```

## 记录口径

- 恢复段样本数：所有标记为丢包的输出帧 × 960，FEC 重建也计入恢复。
- 波形误差：仅在丢包帧区间统计 MAE、RMSE、峰值绝对误差与分段 SNR（参考干净源只用于离线评分）。
- 状态链：每帧一个 token，明细含状态、衰减增益与基音滞后，见 `output/report.md` 与 `output/results.json`。

状态 token：`.` 正常、`R` 恢复交叉淡化、`S` 静音、`P` PLC、`C` 冷启动 PLC、`F` FEC 修复、`p` FEC 回退 PLC、`s` FEC 回退静音。

## 禁止原文回填的保证

1. 接收器只接收 `sim.Packet`；信道把丢包分组的 `Frame/FEC` 置空，接收器拿不到干净源。
2. FEC 负载是发送端独立生成的低通+量化副本，不是原帧；PLC 只读取自身历史输出。
3. `sim.AuditNoBackfill` 对每个丢包恢复帧逐样本比对干净源，若与原文完全相同即报错，并有单元测试 `TestAuditDetectsBackfill` 守护。
4. 干净源仅在接收器之外用于误差评分，不参与任何恢复路径。

说明：这是教学级、纯标准库的 Opus 风格仿真，而非完整 Opus 编解码器；FEC/PLC 的算法语义（带内冗余、基音周期延拓、突发衰减）与真实 Opus 一致，具体实现为简化版。
