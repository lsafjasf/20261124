# 多语言字幕选择器（Go，纯标准库）

修复「切换英语后画面偶尔重置、字幕仍停在中文」的问题。根因是旧实现把
字幕切换和整条播放管线（视频解码器/音频输出）的重建耦合在一起，且语言
匹配结果不确定：当目标语言缺失或存在多个同语种版本时，选择结果可能落到
旧轨上，而管线重建又会重置画面与播放位置。

本实现把两件事彻底拆开：

- `subselector`：纯函数式、确定性的字幕轨选择，输出可审计的回退链；
- `player`：选择结果只通过**字幕渲染器热替换**生效，视频管线与播放时钟
  完全不动。

## 目录结构

| 路径 | 职责 |
| --- | --- |
| `subselector/tag.go` | BCP 47 子集解析、区域隐式脚本、匹配评分 |
| `subselector/selector.go` | 轨道模型、偏好、确定性回退链与 `slog` 审计日志 |
| `player/player.go` | 播放管线抽象，渲染器热替换，位置/状态保持 |
| `cmd/subdemo/main.go` | 端到端演示，打印完整回退链 |
| `*_test.go` | 表驱动测试，含 `-race` 验证 |

仅依赖标准库（`log/slog`、`sort`、`sync`、`context` 等），无第三方包。

## 语言标签与区域差异

解析 `language[-script][-region][-variant…]`，并做区域到脚本的隐式补全，
避免简体/繁体错配：

- `zh-CN`、`zh-SG` 隐含 `Hans`；`zh-TW`、`zh-HK`、`zh-MO` 隐含 `Hant`；
- 因此请求简体时**绝不会**回退到繁体轨（脚本冲突直接判不兼容，`-1` 分）；
- `es-419`、`pt-BR`、`en-GB` 等数字区域/普通区域均支持。

匹配评分（`MatchScore`）：

| 情况 | 分数 |
| --- | --- |
| 规范化后完全相等 | `200`（exact） |
| 语种相同、脚本一致、区域一致 | `140` 区间（high） |
| 语种相同、区域不同 | 低于无区域的通用轨（弱匹配优先安全回退） |
| 脚本冲突或语种不同 | `-1`（禁止选用） |

## 回退链

`Select` 按固定顺序执行，每个阶段都产生一条 `AuditStep` 并输出结构化日志，
未命中的阶段以 `WARN` 级别记录，便于线上排查「为什么还是这轨」：

1. **偏好链**：按用户给出的偏好顺序逐条匹配；无效偏好只告警并跳过；
2. **容器默认轨**：偏好全部未命中时使用 `IsDefault`（强制轨/解说轨除外）；
3. **清单首轨**：没有默认轨时取清单顺序的第一条可用轨；
4. **关闭字幕**：没有任何可用轨时关闭，而不是停留在错误的旧轨上。

同语种多版本的确定性排序（同分时依次比较，全程稳定排序，无 map 遍历）：

1. 轨种：普通轨 → SDH（仅 `PreferSDH` 时提前）→ 强制轨（仅
   `AllowForced` 时允许参与）→ 解说轨永不自动选择；
2. 匹配分（区域精确优先，错误区域低于通用轨）；
3. 默认标记；
4. 清单顺序兜底，保证多次调用结果完全一致、不会抖动。

## 画面与播放位置保持

`player.Player.SwitchLanguage` 只调用 `ApplyDecision` 替换
`Renderer`（字幕解码器/渲染器），代码中刻意不触碰 `position`、`playing`，
也不触发任何管线拆除：

- `PipelineRebuilds()` 在语言切换期间始终为 `0`，只有 `Stop()` 才会重建；
- 重复应用同一决策是带日志的 no-op，UI 重试不会造成反复切换；
- 关闭字幕同样只换渲染器，播放继续、位置不动；
- 所有状态访问经 `sync.RWMutex` 保护，测试在 `-race` 下通过。

## 运行

```bash
go test ./... -race   # 单元测试与并发检查
go run ./cmd/subdemo  # 查看完整回退链与热切换日志
```

演示输出中可核对：每次切换 `position_ms` 保持不变、`pipeline_rebuilds=0`、
`renderer_swaps` 递增，且每个回退阶段（含未命中的 `WARN`）都有日志。
