# edlfix

CMX 3600 EDL 的 DF/NDF 时间码诊断修复器，纯 Go 标准库实现，无第三方依赖。

## 要解决的问题

同一条 EDL 中，上一段按丢帧（DF，`HH:MM:SS;FF`）书写、下一段按非丢帧
（NDF，`HH:MM:SS:FF`）书写时，两种编号指向同一物理帧的字面标签不同，且
差值随时间非线性累积，于是后续每一段都相对前一段发生偏移，整条 EDL 逐段
错位。

**固定秒数补偿是错误方案**：DF 跳过的帧数按分钟变化（29.97 每分钟跳 2 帧、
每第 10 分钟不跳；59.94 每分钟跳 4 帧），漂移量不是常数。加/减固定秒数既
无法对齐所有段落，还会破坏本来正确的段落。本工具因此**只做基于帧号的重算，
不提供任何秒级偏移参数**。

## 修复原理（不改变剪辑意图）

1. 按 reel（引用媒体）确定帧率，支持 `29.97`、`30000/1001`、`59.94`、
   `60000/1001`、`23.976`、`24`、`25` 等写法。
2. 每个时间码先按其**自身标签声明的模式**解析为绝对帧号。
3. 以**帧号作为唯一不变量**，按引用媒体帧率的规范约定重新标注：
   29.97/59.94 输出 DF，其余输出 NDF。
4. 因为帧号不变，源/记录的入出点时长、镜头顺序与剪辑点全部保持原样，变化的
   只是标签书写形式。输出标签恒为 11 字符，按字节等长替换，完整保留 EDL
   排版、注释、TITLE/FCM 等所有非事件行。

## 用法

```bash
# 全局缺省帧率
go run ./cmd/edlfix -input sample.edl -fps 29.97

# 按 reel 分别指定帧率（每行 REEL=帧率，# 为注释）
go run ./cmd/edlfix -input sample.edl -rates reel_rates.txt -output fixed.edl

# 只诊断不落盘；机器可读结果加 -json
go run ./cmd/edlfix -input sample.edl -rates reel_rates.txt -dry-run -json
```

参数：

- `-input`：输入 EDL（必填）
- `-output`：输出路径，缺省为 `<input>.fixed.edl`
- `-fps`：缺省媒体帧率
- `-rates`：reel→帧率映射文件
- `-dry-run`：只诊断不写文件
- `-json`：JSON 诊断输出

必须提供 `-fps` 或 `-rates` 至少其一，否则无法按引用媒体帧率重算。

## 诊断输出

- 报告首先给出**首个不一致时间码**的精确位置（行、列、事件号、reel、
  SRC/REC 字段）、原文、修复结果与对应帧号。
- 随后列出其余所有不一致条目。
- 无法修复的条目**原样保留并说明原因**，包括：
  - `RATE_UNKNOWN`：无法确定该 reel 的引用媒体帧率；
  - `ILLEGAL_LABEL`：标签对该帧率非法（如 29.97 出现 `00:01:00;00` 这类
    落在被跳过帧号上的 DF 标签），无法确定它指向哪一帧；
  - `DF_ON_NONDROP_RATE`：非丢帧媒体上出现 DF 标签，语义有歧义；
  - `FRAME_CONVERT_FAILED` / `RELABEL_FAILED`：帧号转换或重新标注失败。

## 验证

```bash
go test ./...
```

时间码包包含 29.97 与 59.94 全天 24 小时的帧号↔标签穷举往返测试、非法丢帧
标签拦截、经典 DF/NDF 向量对照；修复包覆盖首个不一致定位、帧号不变量、
幂等性以及各类不可修条目的逐字节保留。
